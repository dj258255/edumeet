# 31. CDN 은 조각을 한 번도 캐시하지 않았고, 방송 시작을 기다리던 시청자는 지난 방송을 봤다 (#235)

> 측정 2026-09-24 · 운영(studywithtymee.com, Cloudflare 무료 요금제 → nginx 원본)
> 시청자: 원격 VM(byeolchi-oci, 2코어)의 헤드리스 Chromium 10대 · 합성 방송 H.264 2.5Mbps + Opus · fMP4 2초 조각
> 원본 쪽 수치는 운영 nginx 접근 로그, 시청자 쪽은 브라우저가 받은 응답 헤더(`cf-cache-status`)

재현: `scripts/run-qoe-crosscheck.sh` (`START_MODE=waiting` 이면 시청자가 먼저 붙는다),
`scripts/run-viewer-capacity.sh`, 원본 로그 규칙 자기 시험 `perf/browser/selftest-nginx-log.mjs`

---

## 1. 무엇을 재려고 했나

방송이 시작되는 순간 시청자가 몰린다. 몰릴 때 원본(2코어)이 받는 요청은 CDN 이 얼마나 막아 주느냐에 달렸다.
그래서 **조각 하나를 몇 명이 받았고 그중 몇 번이 원본까지 왔나**를 조각별로 세는 것부터 만들었다.
시청자 쪽 헤더만으로는 병합을 말할 수 없다 - 원본 로그와 나란히 둬야 한다.

## 2. CDN 이 조각을 한 번도 캐시하지 않았다

| 파일 | `cf-cache-status` (같은 방송) |
|---|---|
| `init_<sid>.mp4` | MISS → HIT → HIT |
| `seg_<sid>_NNNNN.m4s` | DYNAMIC · DYNAMIC · DYNAMIC |
| `live.m3u8` | DYNAMIC (의도대로 - 캐시하면 방송이 멈춘 것처럼 보인다) |

nginx 는 조각에 `Cache-Control: public, max-age=4` 를 붙이고 있었다. **Cloudflare 무료 요금제는 `Cache-Control` 이 아니라
확장자 목록으로 캐시 대상을 정한다.** `.m4s` 는 목록에 없다(그 전의 `.ts` 도 없다). 헤더는 한 번도 읽힌 적이 없다.
→ 선언은 있는데 안 쓴다, 열네 번째 ([`../ops/07-declared-but-unused.md`](../ops/07-declared-but-unused.md))

조각 이름을 `.mp4` 로 바꿨다(#239). 플레이어는 확장자가 아니라 플레이리스트의 `EXT-X-MAP` 과 내용으로 판단한다.

| 같은 조건 · 각 1회 | 전 `.m4s` | 후 `.mp4` |
|---|---:|---:|
| 원본 조각 요청 | 920 | **93** |
| 원본 송신 | 607 MB | **62 MB** |
| 조각 하나당 원본 요청 | 10 (= 시청자 수) | **1** |
| 시청자 쪽 조각 HIT | 0 / 920 | 826 / 919 |
| 플레이리스트 원본 요청 | 959 | 983 |
| 정답 끊김 | 0초 | 0.22초 |
| 화면 지연 p50 | 10.4초 | 9.7초 |
| 첫 화면 중앙 | 2,632ms | 2,606ms |
| HLS 404 | - | 0 |

**끊김·지연·첫 화면은 그대로이고 원본 부하만 90% 줄었다.** 캐시 대상이 되면 404 도 캐시될 수 있는데,
nginx 가 `always` 로 404 에도 `max-age=4` 를 붙여 최대 4초로 묶인다. 측정에서는 404 가 0 이었다.

## 3. 방송 시작을 기다리던 시청자

시청자를 먼저 띄워 대기 화면에서 기다리게 하고 30초 뒤 방송을 시작했다(전원이 대기 화면에 닿은 뒤부터 센다).

### 전 — 방송 시작 34초 전에 재생했다 (#241)

| | |
|---|---|
| 시작 → 첫 재생 | **-34초** (10명 전원) |
| 받은 것 | 직전 방송의 조각 119~121 과 그 init |
| 끊김 | 전원 약 36초 (합 364.88초, 네트워크 제한 없음) |
| 시작 ±10초 상태 조회 | 0건 - 기다리지 않고 바로 붙었다 |

상태 응답에는 `broadcasting` 이 있었는데 시청 화면은 **주소가 있는지만** 봤다. 주소는 다시보기 채팅 때문에 방송이 끝나도 남긴다.
그래서 방송과 방송 사이에 화면을 연 사람은 지난 방송의 마지막 몇 초를 보고 멈췄다. 에러는 안 났다.

### 고친 뒤 — 아무도 재생하지 못했다 (#244)

`broadcasting` 을 보게 하자 시청자는 방송이 켜지는 순간 붙었다. 그때는 첫 플레이리스트가 아직 없어 404 다.
오류 처리의 주석은 "방송 시작 직전 404 는 대기다 → `startLoad`" 였는데, **매니페스트를 한 번도 못 받은 hls.js 의
`startLoad` 는 매니페스트를 다시 요청하지 않는다.** 10명 전원이 재생을 한 번도 못 했다.

지금까지 안 보인 것은 지난 방송의 옛 플레이리스트가 늘 남아 있어서 첫 요청이 404 가 아니었기 때문이다.
**버그 하나가 다른 버그를 가리고 있었다.** 고친 것을 같은 조건으로 다시 재지 않았다면 배포된 채로 남았다.

매니페스트 단계 오류는 `loadSource` 로 다시 받고, 간격은 흩는다(#191). 대기 시청자 전원이 같은 순간 404 를 받고
플레이리스트는 CDN 이 캐시하지 않으므로, 고정 간격이면 전원이 같은 순간 원본으로 온다.

### 고친 뒤 — 다시

| 대기 모드 | 전 | #241 만 | **#241 + #244** |
|---|---|---|---|
| 시작 → 첫 재생 | -34초 (지난 방송) | 재생 못 함 (0/10) | **+4.5 ~ +7.6초** (중앙 약 5.4초) |
| 시작 → 첫 매니페스트 | - | 404 뒤 다시 안 받음 | +3.0 ~ +3.4초 |
| 끊김 합 | 364.88초 | - | **0.95초** |
| 화면 지연 p50 | - | - | 6.1초 |
| 원본 조각 요청 / 시청자 쪽 조각 응답 | - | - | 72 / 719 (HIT 647) |

첫 매니페스트가 3초쯤인 것은 발표자의 첫 청크(2초) + ffmpeg 가 첫 조각(2초)을 닫는 시간이다. 그 사이의 404 를 흩은 간격으로 다시 받아 넘겼다.

**하나 적어 둘 것 — 대기 화면의 폴링이 줄을 섰다.** 시작 ±10초의 `GET /meeting/{id}` 는 3초마다 10건씩 **같은 초에** 나갔다.
시청자 10명이 같은 순간 페이지를 열었기 때문이다. 실제 시청자는 흩어져 들어오지만, 공지를 보고 한꺼번에 들어오는 경우라면
3초 간격의 파도가 된다. 지금 규모(초당 10건)에서는 서버 p99 27ms 로 문제가 없어 손대지 않았다.

## 4. 부하 생성기가 먼저 무너진다 — 시청자는 10명까지만 믿는다

스로틀 없이 시청자 수만 늘렸다. 스로틀이 없는데 끊기면 그건 네트워크가 아니라 생성기의 한계다(#160).

| 시청자 | 정답 끊김 합 | 끊긴 시청자 | 첫 재생 중앙 | 원격 VM CPU ≥95% 인 표본 |
|---:|---:|---:|---:|---:|
| 10 | 0초 | 0/10 | 2,615ms | 41% |
| 20 | 1,019.8초 | **20/20** | 6,365ms | 57% |
| 30 | 1,451.7초 | **30/30** | 12,050ms | 54% |

같은 창에서 합성 방송은 조각을 하나도 놓치지 않았고(기대 175 · 보냄 175) 화면 지연 p50 은 10.4 → 12.6초였다 - 서버는 멀쩡했다.
**20명부터는 2코어 VM 이 브라우저 20개의 영상 해독을 못 따라간다.** 이 VM 으로 잰 20명 이상의 숫자는 조건 불성립이다.
그래서 이 문서의 측정은 전부 10명이다.

## 5. 한계

- **시청자가 한 VM, 즉 한 Cloudflare 거점에서 붙었다.** 병합의 최선 조건이다. 실제 원본 요청은 `조각 수 × 시청자가 흩어진 거점 수` 로 는다
- 전후 각 1회다. 원본 요청 수(920 → 93)는 구조로 정해지는 값이라 회차 편차가 작지만, 끊김·지연은 한 회차 값이다
- 10명이다. 몰림의 크기(수백 명)는 이 생성기로 못 만든다 - 원본 요청이 시청자 수가 아니라 거점 수에 비례한다는 **구조**를 보인 것이지, 수백 명에서의 지연을 보인 것이 아니다
- 운영 측정이라 배포와 겹치면 방송이 끊긴다. 측정 중에는 백엔드·인프라를 머지하지 않았다
