# 어디서 재야 하는가 — 노트북과 OCI 사이

> 지금까지의 측정은 **전부 노트북에서** 돌았다. 문서에도 그렇게 적어 뒀다.
> 여기서는 **무엇을 OCI 로 옮겨야 하고 무엇은 옮기면 안 되는지**를 정한다.

---

## 왜 이 질문이 나왔나

측정의 목적이 두 가지로 갈린다.

| 목적 | 질문 | 필요한 것 |
|---|---|---|
| **상대 비교** | *"고치니 나아졌나"* | 조건이 같기만 하면 된다 |
| **용량** | *"이 하드웨어가 몇 명 받나"* | **그 하드웨어여야 한다** |

지금까지 잰 것은 대부분 앞쪽이다. **뒤쪽은 노트북에서 잴 수 없다.**

---

## 그런데 OCI 안에서 부하를 걸면 안 된다

서버 상태를 먼저 봤다.

```
코어           2 (aarch64)
메모리         11Gi (여유 8.6Gi)
load average   1.13  ← 2코어 기준 절반 이상이 이미 쓰이고 있다
컨테이너       14개
```

**우리 앱은 그중 3개다.** 나머지 11개는 다른 프로젝트다
(`a02-mdl-storm-load`, grafana·influxdb·loki·prometheus·alloy·cadvisor…).

여기서 k6 까지 돌리면 **k6 가 앱과 2코어를 나눠 쓴다.**
노트북(12코어)에서 같이 돌렸을 때보다 **오염이 훨씬 심하다.**

> 부하 생성기를 측정 대상 안에 두면, 재는 것은 앱의 한계가 아니라
> **"부하 생성기가 얼마나 방해했는가"** 가 된다.

---

## 그래서 이렇게 나눈다

```
앱 + MySQL + Redis   →  OCI      (측정 대상)
k6                   →  노트북    (네트워크 너머)
```

부수 효과가 하나 있는데 **오히려 현실적이다.**
실사용자도 네트워크 너머에 있다. 노트북 localhost 측정에는 그게 아예 없었다.

---

## 네트워크 바닥값을 먼저 쟀다

앞으로 재는 모든 지연에서 **이만큼은 서버 탓이 아니다.**

```
k6 run -e BASE=http://<host>:8080 k6/network-floor.js
```

인증 거부(401) 경로를 쓴다. **JWT 필터에서 끊기므로 DB 를 타지 않는다** —
남는 것이 네트워크 + 서블릿 왕복이다.

| | |
|---|---:|
| VU / 시간 | 5 / 15초 |
| 요청 | 4,247 (283 req/s) |
| **min** | **10.97 ms** |
| **p50** | **15.14 ms** |
| **p95** | **27.98 ms** |
| p99 | 54.56 ms |
| max | 167.01 ms |

**읽는 법**: OCI 측정의 p95 에는 **약 28ms 가 상수로 얹혀 있다.**
서버 작업이 28ms 보다 훨씬 크면 무시해도 되고, 비슷하면 지연의 절반이 네트워크다.

> **k6 의 `http_req_failed` 를 임계값으로 쓰지 않는다.**
> k6 는 non-2xx 를 전부 실패로 센다. 401 이 정상 응답인 테스트에서는
> 이 지표가 100% 로 나오는데 **실패가 아니다.** `checks` 로 판정한다.
> 스크립트에 그렇게 적어 뒀다.

## 무엇을 어디서

| 측정 | 어디서 | 왜 |
|---|---|---|
| N+1 전/후 | **노트북** | 목적이 상대 비교다. 게다가 응답이 404KB 라 **집 인터넷이 병목**이 된다 |
| 세션 정원 동시성 | **OCI** | 요청이 작고, 잠금 동작은 하드웨어에 따라 달라진다 |
| **채팅 동시 접속 상한** | **OCI** | 이 프로젝트의 중심 질문. WebSocket 이라 페이로드가 작아 대역폭 문제도 없다 |
| 큐 OOM 재현 | **노트북** | 힙을 512MB 로 **통제**해야 재현된다. 서버에선 통제가 안 된다 |
| HLS egress | **불가** | RoomComposite 는 4코어. 지금 여유가 0.8코어다 |

## 남은 한계 (정직하게)

- **옆 프로젝트 컨테이너 11개가 계속 돈다.** load average 1.13 이 기준선이다.
  이걸 멈추지 않는 한 OCI 측정에는 **통제되지 않은 배경 부하**가 섞인다.
  절대 수치를 주장하려면 멈추고 다시 재야 한다.
- **집 인터넷 상·하향이 측정 상한이다.** 응답이 큰 엔드포인트는 서버가 아니라 회선이 먼저 막힌다.
- ICMP 가 막혀 있어 RTT 를 ping 으로 못 잰다. 위 숫자는 **HTTP 왕복**이다.
