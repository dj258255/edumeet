# 33. 재생 속도로 지연을 따라잡는 것을 기각했다 (#233)

> 측정 2026-09-24 · 운영(studywithtymee.com) · 원격 시청자 10 · fMP4 2초 조각 · 각 조건 2회
> 정상망 = 제한 없음 · 제한망 = 60~120초 3Mbps → 120~125초 끊김 → 125~180초 3Mbps

재현: `CATCHUP_RATE=1.1` 또는 `CATCHUP_MODE=adaptive` 로 `scripts/run-qoe-crosscheck.sh`.
자막 읽기 속도: `perf/captions/reading-speed.py`

---

## 1. 문제와 기준

실제 화면 지연이 9~10초다(#198). 교육 기준 5초를 넘는다. hls.js 는 지연이 목표보다 크면 재생 속도를 잠깐 올려
따라잡을 수 있다(`maxLiveSyncPlaybackRate`). 대가가 둘이다 — **자막도 그만큼 빨리 지나가고**, 버퍼를 깎으니 **끊김이 는다**(#193).

측정 전에 적은 기준:

- 자막: 읽기 속도 상한을 넘는 자막이 5% 이하
- 끊김: 제한망에서 끊김이 지금보다 늘지 않는다
- **둘을 지키는 속도가 없으면 기각한다**

## 2. 자막은 문제가 아니었다

Netflix 한국어 가이드의 성인 읽기 속도 12자/초(SDH 14)를 기준으로, 팀 강의 표본의 발화 최대 5.9자/초에서는
**2배속까지 상한을 안 넘는다**(`perf/captions/out/reading-speed.md`). 표본이 한 강의라는 한계가 있다.
자막 축은 통과 — 남은 것은 끊김이다.

## 3. 처음 11회차는 따라잡기가 꺼진 채였다

`CATCHUP_RATE=1.5` 가 준비 로그에 찍혔는데 결과의 재생 속도는 한 번도 1을 넘지 않았다.
원격 시청자 명령이 인자를 손으로 다시 나열하다 그 옵션을 빠뜨렸다(#242).
**요청한 설정이 적용됐는지를 회차마다 대조**하게 고친 뒤(불일치면 조건 불성립) 전부 다시 쟀다.

## 4. 항상 켬 (2.5Mbps 송출)

| 따라잡기 | 정상망 지연 p50 | 정상망 끊김 | 제한망 끊김 합 | 제한망 연쇄 끊김 |
|---|---:|---:|---:|---:|
| 끔 | 9.0 / 10.8초 | 0 | 219 / 204초 | 231 / 263 |
| 1.1 | **4.7 / 5.1초** | 0 | 305 / 263초 | 243 / 285 |
| 1.25 | 4.7 / 4.9초 | 1 | 394 / 322초 | 178 / 302 |
| 1.5 | 5.0 / 5.0초 | 1~3 | 378 / 340초 | 300 / 313 |

정상망에서는 지연이 절반이 된다. 제한망에서는 지연은 그대로이고 끊김만 30~65% 는다. **항상 켬은 기준 탈락.**

처음에 "지연 대부분이 플레이어 앞단에서 생긴다" 고 추정했는데 틀렸다. 제한망 한 쌍만 보고 한 추정이었다.
정상망에서 플레이어가 라이브 끝보다 약 5초 뒤로 밀려 있었고 1.1배가 그걸 당겼다.

## 5. 조건부 — 망이 좋을 때만

최근 30초 끊김 없음 · 앞쪽 버퍼 · 대역 여유일 때만 1.1배로 켠다.

**v1 (2.5Mbps 송출)**: 정상망 지연 10.7 → 5.2초, 제한망 연쇄 끊김 약 +30% → 탈락. 원인 둘을 코드에서 찾았다.

- 우리 방송은 master 없는 미디어 플레이리스트라 hls.js 가 **스트림 비트레이트를 모른다.** 정책은 그때 대역 조건을 건너뛰어 3Mbps 망에서도 켰다
- 켜면 버퍼를 당겨 문턱 아래로 → 꺼짐 → 회복 → 켜짐. 시청자당 3분에 약 21번 바뀌었다

**v2**: 최근 조각 크기로 비트레이트를 추정하고 모르면 켜지 않는다. 켤 때(버퍼 2.5초 · 대역 1.5배)와 끌 때(1.0초 · 1.2배)의 문턱을 나눴다.
hls.js 는 설정을 1 로 내려도 이미 올린 재생 속도를 되돌리지 않아(1 이면 일찍 return) 끌 때 직접 1 로 되돌린다.

| 1.5Mbps 송출 (#199 이후 표준) | 정상망 지연 p50 | 정상망 끊김 | 제한망 끊김 합 | 제한망 연쇄 끊김 | 켜진 비율 | 전환(시청자당 3분) |
|---|---:|---:|---:|---:|---:|---:|
| 끔 | 7.8 / 8.5초 | 0 | 8.1 / 25.4초 | 0 / 9 | - | - |
| 조건부 v2 | **5.0 / 4.4초** | 0 | 55.6 / 27.6초 | **12 / 12** | 정상 94~95% · 제한 35~37% | 2.2 / 5.8 |

깜빡임은 약 21회에서 2회로 줄었고 정상망 지연은 여전히 절반 가까이다. **제한망 연쇄 끊김은 여전히 는다** (끔 평균 4.5 → 12).

## 6. 결정 — 기각 (기본값 끔)

사전 기준대로 기각한다. 조건부 정책은 진단 설정(`catchupMode=adaptive`)으로 남긴다.

v3 로 문턱을 더 조이면 이 그리드는 통과할 가능성이 높다. **하지 않았다.** 이 그리드의 제한망 일정에 맞춘 상수는
그 일정만 통과한다 — 지금까지의 상수 근거를 일반 원리로만 적은 이유와 같다.

우선순위의 근거는 #234 의 SLO 다. **끊김 비율은 SLO 이고 지연은 아니다.** 지연을 줄이는 장치가 끊김 예산을
태우면 그 장치를 끈다. 5초 목표가 필요하다면 따라잡기가 아니라 앞단(조각 길이 · 송출 청크)에서 줄여야 하는데,
1초 조각은 이미 끊김 +14~29% 로 기각됐다(#198).
