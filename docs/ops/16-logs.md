# 로그를 지표 옆에 뒀다 (#166)

> 2026-08-29 · 경보는 있는데 그 뒤에 볼 것이 없던 문제

## 0. 무엇이 없었나

관측 스택은 이미 서 있었다. Prometheus 가 지표를 긁고, 규칙이 평가되고,
Alertmanager 가 사람에게 보낸다.

**그런데 울린 뒤에 볼 것이 없었다.**

[`04-observability.md`](04-observability.md) 와 경보 규칙에 이렇게 적어 뒀다.

> 급성 붕괴(순증 1만/s 이상)에서는 이 경보가 늦다. **그때는 사후 기록으로 읽는다.**

그 사후 기록을 보려면 **서버에 들어가 `docker logs` 를 쳐야** 했다.
그리고 컨테이너를 다시 만들면 그것도 사라진다.

**지표는 "몇 건 버렸다" 까지만 말한다.** 어느 방에서 언제 버렸는지는 로그에만 있다.
조용히 실패하는 것들이 특히 그렇다 — 자막 드롭, 큐 상한, 세션 강제 종료.

---

## 1. 네 조각

```
앱 ──JSON 로그──> 컨테이너 stdout ──Alloy──> Loki ──> Grafana
      (logback)                      (수집)   (저장)   (지표와 한 화면)
```

| | 무엇 | 왜 그것 |
|---|---|---|
| 형식 | `logstash-logback-encoder` | Loki 가 필드로 걸러야 한다 |
| 맥락 | MDC(`requestId`, `meetingId`) | 거를 것이 없으면 모아 놔도 못 쓴다 |
| 수집 | Grafana Alloy | Promtail 은 폐기됐다 |
| 저장 | Loki 3.3 단일 노드 | 2 OCPU 에 읽기·쓰기를 나눌 이유가 없다 |

---

## 2. 개발과 운영의 형식을 나눴다

```
개발   사람이 읽는다. docker logs / IDE 콘솔에서 바로 보여야 한다
운영   Loki 가 읽는다. 필드로 걸러야 하므로 JSON 이다
```

하나로 통일하면 한쪽이 불편해진다. 개발에서 JSON 을 보면 눈으로 못 읽고,
운영에서 평문을 쓰면 *"meetingId=3 인 것만"* 을 정규식으로 짜야 한다.
그리고 **그 정규식은 메시지 형식이 조금만 바뀌면 조용히 0건이 된다.**

### 스택 트레이스를 자른다

20 프레임 · 3,000자에서 자르고 프레임워크 프레임은 뺀다.
안 자르면 **예외 하나가 로그 수백 줄**이 되고, Loki 의 청크가 그것으로 찬다.
정작 보려던 앞뒤 맥락이 보존 기간 밖으로 밀려난다.

---

## 3. MDC 를 안 지우면 로그가 틀린 답을 준다

톰캣은 스레드를 재사용한다. 요청이 끝나고 MDC 를 안 지우면
**다음 요청이 남의 회의 번호를 달고 찍힌다.**

```java
} finally {
    MDC.remove(REQUEST_ID);
    MDC.remove(MEETING_ID);
}
```

**틀린 답은 아무 답도 없는 것보다 나쁘다.** 없으면 다른 데를 찾지만,
틀린 값이 있으면 그것을 믿고 엉뚱한 데를 판다.

### 요청 아이디를 서버가 만든다

한 요청이 여러 줄을 남긴다. 묶을 것이 없으면 **동시 요청이 섞여**
어느 줄이 어느 요청인지 모른다. 부하 상황에서 특히 그렇다 —
**로그가 가장 필요한 순간이 가장 섞이는 순간이다.**

클라이언트가 `X-Request-Id` 를 보내면 그것을 쓴다.
응답에도 같은 값을 실어, 문의가 들어왔을 때 그 값으로 로그를 찾는다.

## 4. 수집기를 무엇으로 할 것인가

| | 판단 |
|---|---|
| Promtail | **기각.** 2025년에 폐기 예고됐고 지원이 끝났다 |
| Loki 도커 드라이버 | **기각.** 에이전트 컨테이너가 없어 메모리는 덜 먹는다. 그런데 **호스트에 플러그인을 깔아야 해서 compose 파일만으로 재현이 안 된다** |
| **Grafana Alloy** | **채택.** compose 안에 들어가고 컨테이너를 알아서 찾는다 |

### 라벨을 적게 둔다

Loki 는 **라벨 조합마다 스트림을 만든다.** 라벨이 많으면 스트림이 쪼개져
인덱스가 커지고 질의가 느려진다.

```
라벨      container, level, job     거를 것만
JSON 필드  meetingId, requestId      질의 시점에 | json 으로 푼다
```

`level` 만 라벨로 올린 이유는 *"에러만 보여줘"* 가 가장 잦은 질의이고,
값의 가짓수가 적어 스트림이 안 쪼개지기 때문이다.

### 관측 스택 자신의 로그는 뺀다

Loki 가 느려지면 그 로그가 또 Loki 로 가서 더 느려진다. **되먹임이다.**

## 5. ★ 실제로 띄워 보고 결함을 하나 잡았다

설정만 쓰고 끝내지 않았다. 서버에 격리해서 띄우고 **Loki 에 실제로 닿는지** 물었다.

```
$ curl .../loki/api/v1/label/container/values
{"data":["edumeet-app"]}          <- 앱만 있다
```

**앱 로그는 들어오는데 mysql·redis 가 없었다.** Alloy 로그를 보니

```
status=400 ... entry for stream '{container="edumeet-mysql"}'
has timestamp too old: 2026-08-24T22:10:04Z
```

`reject_old_samples_max_age: 24h` 로 뒀는데, **조용한 컨테이너**는 마지막으로
뭔가를 찍은 게 며칠 전이라 수집기가 처음 붙어 밀어 넣을 때 전부 거절됐다.

**증상이 고약하다.** 앱 로그는 잘 들어와서 *"되고 있다"* 로 보이는데
조용한 컨테이너만 없다. 그리고 **그 컨테이너가 조용한 이유를 알고 싶을 때
바로 그 로그가 없다.**

보존 기간과 같은 값(168h)으로 맞추고 다시 확인했다.

```
container 값   edumeet-app, edumeet-mysql
Alloy 에러     0건
```

`service_name` 라벨도 같이 뺐다. Loki 3.x 가 알아서 만드는데
`container` 와 같은 값이라 **스트림만 쪼갠다.**

## 6. 형식이 조용히 깨지는 것을 시험으로 막았다

`<springProfile>` 은 **조용히 안 걸린다.** 이름을 잘못 적거나 블록이 어긋나면
예외 없이 그 블록만 무시되고 로그는 평문으로 나간다.

그러면 **Loki 는 계속 로그를 받는다. 받기는 받는데 필드가 없다.**
`| json | meetingId="3"` 이 에러가 아니라 **0건**을 낸다.
이 저장소에서 여러 번 잡은 모양이다 — 있는데 아무 일도 안 하는 설정.

그래서 **실제로 한 줄 찍어서 그 줄이 JSON 으로 파싱되는지** 본다.
어펜더 종류를 보는 것보다 낫다 — 인코더가 붙어 있어도 출력이 JSON 이 아닐 수 있다.

**되돌려서 잡히는 것을 확인했다.** 프로필 이름을 `produciton` 으로 오타 내니 실패한다.

## 7. 보존 기간

| | |
|---|---|
| 지표(Prometheus) | 15일 |
| **로그(Loki)** | **7일** |

로그가 더 짧은 이유는 **부피**다. 이 서버는 46GB 에 이미 80% 가 차 있고,
무제한으로 두면 로그가 조용히 디스크를 먹어 **MySQL 이 먼저 죽는다.**

`retention_period` 만 적으면 안 지워진다. **`compactor` 의 `retention_enabled` 를
같이 켜야** 실제로 삭제된다. 이것도 "설정은 있는데 안 도는" 자리다.

---

## 8. 아직 안 한 것

- **분산 추적**(Tempo 등)을 안 붙였다. 자막 경로가 파이썬 → 자바를 건너지만,
  그 홉 비용은 이미 페이로드에 시각 셋(`spokenAt` · `receivedAt` · `publishedAt`)으로
  담아 재고 있다. **추적 백엔드를 2코어에 하나 더 띄울 근거가 아직 없다**
- **로그 기반 경보**를 안 넣었다. 지표로 셀 수 있는 것을 로그로 세지 않는다
- 파이썬·MCP 로그는 JSON 이 아니다. 앱만 먼저 했다
