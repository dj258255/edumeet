# 자막 검색 — 재고 나서 붙였다

> **#140.** 질의 30개로 다섯 방식을 비교하고, 그 결과대로 구현을 정했다.

---

## 기각해 둔 것을 뒤집으려면 근거가 필요하다

[`ops/11`](11-mcp-transcript-server.md) 의 "안 한 것" 표에 이렇게 적어 뒀다.

> **임베딩·벡터 검색** — 자막은 조각 단위 텍스트고 질의는 대부분 용어다.
> **의미 검색이 필요하다는 근거가 아직 없다**

**그래서 순서를 못 박았다. 재고 나서 붙인다. 붙이고 나서 재지 않는다.**

## 재려고 보니 비교 대상이 허수아비였다

기존 구현은 **질의 문자열 전체**를 부분문자열로 찾고 있었다.

```
"비관적 잠금"                 →  1건
"비관적 잠금 어디서 설명했지"   →  0건
```

질문 형태는 무조건 0건이다. **의미 때문이 아니라 구현 때문이다.**

여기에 임베딩을 붙여 *"0% → 70%"* 라고 적으면 그건 측정이 아니다.
**토큰 단위로만 바꿔도 상당 부분이 해결될 수 있고, 그러면 모델을 넣을 이유가 없다.**

그래서 모델 없는 베이스라인을 두 개 더 만들어 같이 쟀다.

---

## 질의 세트

| | |
|---|---|
| 용어형 **15** | 강의에서 쓴 말 그대로. **어휘 겹침 평균 93%** |
| 질문형 **15** | 사람이 실제로 묻는 방식. **어휘 겹침 평균 17%** |

용어형을 안 넣으면 *"새 방식이 좋다"* 가 공짜로 나온다.

### 라벨을 인위로 비틀지 않았다

처음엔 *"질문형에는 자막에 나오는 단어가 하나도 없어야 한다"* 는 규칙을 넣었다.
**그건 결론을 미리 정해 놓는 것이다** — 그렇게 만들면 어떤 렉시컬 방식도 질 수밖에 없고,
임베딩이 이기는 것이 측정이 아니라 설계의 결과가 된다.

대신 **어휘 겹침을 같이 보고한다.** 겹침이 낮은데 렉시컬이 찾으면 우연이고,
높은데 임베딩만 찾으면 그건 이상하다. **결론을 읽을 때 이 값을 같이 봐야 한다.**

---

## 결과 (조각 60개 · 질의 30개 · k=5)

| 방식 | 전체 recall@5 | 질문형 | MRR | 0건 | 질의당 | 추가 비용 |
|---|---:|---:|---:|---:|---:|---|
| A 문자열 전체 (전) | 50% | **0%** | 0.50 | 15/30 | 0.03ms | — |
| B 토큰 매칭 | 72% | 43% | 0.72 | 8/30 | 0.03ms | 없음 |
| **B′ 문자 2-gram** | **77%** | **54%** | 0.77 | 5/30 | 0.06ms | **없음** |
| C 임베딩 단독 | 80% | 60% | 0.80 | 2/30 | 15.4ms | venv 857MB |
| **D 하이브리드** | **85%** | **70%** | 0.81 | **0/30** | 16.9ms | venv 857MB |

### ★ 가장 큰 개선은 모델이 아니었다

```
질문형 재현율   0%  →  54%      문자열 전체 → 문자 2-gram.  값이 공짜다
              54%  →  70%      + 로컬 임베딩.  질의 지연 250배, venv 857MB
```

**54%p 를 공짜로 얻고, 그다음 16%p 에 857MB 를 낸다.**

### 용어형에서는 임베딩이 렉시컬을 못 이긴다

다섯 방식 모두 재현율 100% 다. 그런데 MRR 은 임베딩 단독이 **0.97** 로 오히려 낮다 —
정확히 일치하는 조각을 1등에 못 놓는 경우가 있다.
**렉시컬을 버리면 잘하던 것을 잃는다.** 하이브리드가 필요한 이유다.

---

## 그래서 이렇게 넣었다

```
① 질의 문자열 전체가 그대로 있는 조각        조각 순서로
② 없으면 문자 2-gram 유사도 순위
③ 의미 검색이 켜져 있으면 ②와 RRF 로 병합
```

측정한 대로 나온다 — **용어형 100% / MRR 1.00 / 0.0ms**, 질문형 54%(끄면) · 70%(켜면).

### ★ ③을 "②가 0건일 때" 로 두면 영원히 안 돈다

처음에 계단식 폴백으로 짰다. **한 번도 실행되지 않았다.**

2-gram 은 겹치는 조각이 하나만 있어도 결과를 내므로 그 조건이 성립하지 않는다.
측정에서 발견했다 — 켜고 쟀는데 숫자가 꺼진 것과 똑같았다.

> **"선언은 있는데 아무도 안 쓴다"** 를 또 만들 뻔했다
> ([`ops/07`](07-declared-but-unused.md)). 이번엔 **측정이 잡았다.**

측정에서 이긴 것은 폴백이 아니라 **두 순위를 합치는 것**이었다.

### 점수를 더하지 않고 순위만 쓴다

코사인 0.83 과 2-gram 0.21 을 더하면 **척도가 큰 쪽이 항상 이긴다.**
두 값은 단위가 다르다. 순위는 단위가 없다 — 그래서 RRF 다.

### 정확 일치는 모델을 안 부른다

`Redis` 를 넣었는데 15ms 를 물릴 이유가 없다. ①에서 끊는다.
시험이 그것을 고정한다 — `test_exact_stage_never_calls_the_model`.

## 임베딩은 선택적 의존성이다

```bash
pip install -r requirements.txt            # 렉시컬만. 질문형 54%
pip install -r requirements-semantic.txt   # + torch. 질문형 70%
EDUMEET_SEMANTIC_SEARCH=1                  # 설치만으로는 안 켜진다
```

**설치돼 있다는 이유만으로 켜지 않는다.** 켜면 모든 질의에 15ms 가 붙는데,
용어로만 찾는 사용자에게 그 비용을 물릴 이유가 없다.

| | |
|---|---|
| 모델 | `intfloat/multilingual-e5-small` · 384차원 · 118M 파라미터 |
| 색인 | 조각 60개 **0.32초** / **0.09MB** |
| venv | 렉시컬만 약 60MB → torch 포함 **857MB** |
| 첫 질의 | 모델 로드 포함 **약 350ms**. 이후 17ms |

**유료 키가 필요 없다.** 이 저장소가 AI 서비스를 못 띄우는 이유 세 개 중
하나가 사라졌다 — 남은 것은 트리거 경로와 자막 소스다.

### 꺼져 있다는 것을 사용자에게 말한다

질문형에서 못 찾았는데 그 이유를 안 알려 주면 *"그런 얘기를 안 했다"* 로 읽힌다.
**용어 사전 때와 같은 실수다**([`ops/11`](11-mcp-transcript-server.md)).

```
※ 의미 검색이 꺼져 있다(EDUMEET_SEMANTIC_SEARCH 가 꺼져 있다).
   질문 형태로 물었다면 강의에서 쓸 법한 말로 다시 찾아본다.
```

## 한계

| | |
|---|---|
| **합성 코퍼스다** | 운영 자막을 쓰면 재현이 안 되고 공개할 것도 아니다. 실제 강의는 조각이 더 길고 잡음이 많다 |
| **60조각이다** | 한 시간짜리 강의는 수백~수천이다. 색인 시간은 선형이지만 질의 지연은 다시 재야 한다 |
| **정답을 내가 라벨링했다** | 어휘 겹침을 같이 보고해 편향을 드러냈지만, 라벨 자체는 한 사람의 판단이다 |
| **회의 하나 안에서만 찾는다** | 회의 간 검색은 색인 전략이 다르다. 필요해지면 그때 |
| **2 OCPU 에서 안 재 봤다** | 이 수치는 개발 머신(arm64)이다. 서버에서는 더 느리다 |

## 안 한 것

| | 근거 |
|---|---|
| 벡터 DB (pgvector·Qdrant) | 조각 60개에 **0.09MB** 다. numpy 행렬 하나로 충분하다. 회의 간 검색이 필요해지면 그때 |
| 형태소 분석기 | 의존성이 하나 늘고 **그 품질이 검색 품질에 섞인다.** 문자 2-gram 이 사전 없이 그 일부를 흡수한다 |
| 재순위(cross-encoder) | 조각 60개에서 상위 5개를 다시 정렬할 이유가 없다. 후보가 수백 개가 되면 그때 |
| 서버 쪽 임베딩 | MCP 서버는 컨테이너가 아니라 클라이언트 옆에서 돈다. 모델도 거기 두는 것이 일관된다 |
