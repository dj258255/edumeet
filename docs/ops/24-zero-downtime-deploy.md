# 24. 배포마다 20.5초씩 끊고 있었다 (#180)

[#173](20-disk.md) 에서 다른 것을 재다가 나온 숫자다.

```
재시작 중단 시간   20.5초
```

종료 신호부터 다시 응답할 때까지 모든 요청이 거부된다.
배포가 컨테이너를 **지우고 다시 만들기** 때문에, 그 사이에는 아무것도 없다.

---

## 더 나쁜 쪽은 중단이 아니었다

지금 순서는 이렇다.

```
옛 컨테이너를 내린다  ->  새 이미지로 다시 만든다  ->  뜨는지 본다
```

**새 것이 뜨는지 알기 전에 옛 것을 이미 지운다.**
새 이미지가 안 뜨면 되돌릴 것이 없다 — 이전 이미지를 다시 받아서 다시 띄워야 하고,
그동안 서비스는 계속 없다.

중단 20.5초는 재면 나오는 숫자지만, 이쪽은 **실패한 배포에서만** 드러난다.

---

## 슬롯 둘을 번갈아 쓴다

```
1. 지금 서비스 중인 슬롯을 nginx 설정에서 읽는다
2. 반대 슬롯에 새 이미지를 띄운다          <- 서비스는 계속 옛 슬롯이 한다
3. 새 슬롯이 healthy 가 될 때까지 기다린다
4. nginx 를 새 슬롯으로 옮기고 다시 읽는다  <- 전환점
5. 잠깐 두었다가 옛 슬롯을 내린다          <- 처리 중이던 요청을 끝내게
```

3에서 못 뜨면 **새 슬롯만 지우고 그만둔다.** nginx 는 그대로고, 옛 슬롯은 내려간 적이 없다.

| | 전 | 후 |
|---|---|---|
| 배포 중 중단 | 20.5초 | (아래에서 잰다) |
| 새 이미지가 안 뜰 때 | 서비스가 없다 | **아무 일도 안 일어난다** |

---

## "지금 어느 쪽이 서비스 중인가" 를 어디에 두나

이건 **상태**다. 배포 때마다 덮어쓰면 안 된다.

nginx 설정 본문에 두면 배포가 그 파일을 통째로 설치하므로 상태가 매번 지워진다.
그래서 upstream 만 별도 파일로 빼고, **이미 있으면 배포가 덮어쓰지 않는다.**
저장소의 것은 처음 한 번을 위한 씨앗이다.

```nginx
# edumeet.conf
include /etc/nginx/conf.d/edumeet-upstream.inc;
```

확장자가 `.conf` 가 아닌 이유는, `conf.d/*.conf` 를 nginx 가 자동으로 읽기 때문이다.
`.conf` 로 두면 `include` 하기 전에 이미 한 번 읽혀 `upstream` 이 중복 정의된다.

---

## 대가 — 두 슬롯이 같이 떠 있는 동안 방이 갈린다

채팅 중개자가 **메모리에 있다.** 두 슬롯이 동시에 떠 있는 창에서는
양쪽에 붙은 사람이 서로의 메시지를 못 본다.

그래서 드레인을 길게 두지 않는다. HTTP 요청은 몇 초면 끝나고,
WebSocket 은 끊겨서 다시 붙는다 — 재접속은 이미 재 뒀다
(150/150 · p95 292ms, [`../performance/09-chat-capacity-oci.md`](../performance/09-chat-capacity-oci.md)).

**끊긴 사이의 자막은 구독 시점에 메워 준다**([#165](../performance/15-caption-backpressure-landing.md)),
**지난 대화는 입장 시 불러온다**([#168](17-broadcast-liveness.md)).
그 둘이 없었으면 이 전환이 사용자에게 그대로 보였을 것이다.

### 그래서 두 슬롯을 오래 띄워 두지 않는다

프로필로 가둬서 `docker compose up -d` 만으로는 **둘 다 안 뜬다.**
앱 슬롯은 배포 스크립트만 건드린다.

---

## 관측이 슬롯을 따라가게 했다

**스크레이프.** 별칭(`app`) 으로 긁으면 전환 중에 DNS 가 번갈아 답해
지표가 두 프로세스 사이를 오간다. 슬롯 이름으로 둘 다 긁는다.

**경보.** 안 도는 슬롯은 늘 `up=0` 이다. 슬롯마다 물으면 **상시 울린다** —
[#178](22-alerts-that-never-ran.md) 에서 로그 경보가 딱 그 모양이었다.
묻고 싶은 것은 "하나가 안 뜬다" 가 아니라 **"하나도 안 뜬다"** 이므로 합쳐서 묻는다.

```promql
sum(up{job="edumeet-app"}) == 0 or absent(up{job="edumeet-app"})
```

**로그.** 수집기가 `edumeet-` 로 시작하는 컨테이너를 모으게 돼 있어
`edumeet-app-blue` · `edumeet-app-green` 이 그대로 잡힌다. 고칠 것이 없었다.

---

## 곁가지 — 앱 포트를 인터넷에 열어 두고 있었다

옛 정의는 `8080:8080` 이었다. 바인딩 주소를 안 쓰면 `0.0.0.0` 이다.
nginx 는 같은 호스트에서 붙으므로 밖에 열 이유가 없었고,
지금까지는 클라우드 보안 목록만 그것을 막고 있었다.

슬롯을 만들면서 `127.0.0.1` 로 묶었다. 관리 포트에는 이미 같은 기준을 적용해 뒀는데
([#28](04-observability.md)) 서비스 포트만 예외였다.
