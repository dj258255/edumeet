# 실패한 CI 가 master 에 들어갔다 (#171)

> 2026-08-30 · 사고 기록과 그 뒤에 건 장치

## 0. 무슨 일이 있었나

방송 생존성 작업(#168)을 머지했다. **CI 백엔드가 빨간 채로 들어갔다.**

```
$ gh pr merge 166 --squash --delete-branch
✓ merged

$ gh run list --branch master --limit 1
failure  CI  feat(broadcast): 배포가 끊은 방송을 정리하고... (#166)
```

`gh pr merge` 는 **체크가 실패해도 머지한다.** 막는 것은 브랜치 보호인데
이 저장소에는 걸려 있지 않았다.

```
$ gh api repos/dj258255/edumeet/branches/master/protection
{"message":"Branch not protected","status":"404"}
```

### 무엇이 깨져 있었나

`SchemaExportTest` 가 컨텍스트 로딩에서 실패했다.

```
Table "MEETING" not found (this database is empty)
  at BroadcastService.reconcileOnStartup
```

그 시험은 엔티티에서 MySQL DDL 을 **파일로만** 뽑는다. H2 에는 테이블이 안 만들어진다.
거기서 기동 훅의 조회가 터져 **앱이 아예 안 떴다.**

**정리하려다 앱을 못 뜨게 만들었다.** 청소 작업이 기동 조건이 된 것이다.

---

## 1. 왜 잡들을 그대로 필수로 걸 수 없나

이 저장소의 CI 는 **경로 필터로 잡을 건너뛴다**(#99). 모노레포라
문서만 고쳐도 백엔드 전체를 빌드하는 것은 낭비이기 때문이다.

```
문서만 고친 PR
  백엔드 테스트    skipping
  프론트 빌드      skipping
  AI 서비스 테스트  skipping
```

이것들을 그대로 필수 체크로 걸면, **건너뛴 잡을 GitHub 이 어떻게 세는지**에
결과가 달라진다. 잘못 걸면 **문서만 고친 PR 이 영영 머지 안 된다.**

> **막으려던 것보다 나쁜 결과다.** 그러면 사람이 보호를 꺼 버리고,
> 그때부터는 아무것도 안 막는다.

## 2. 그래서 관문을 하나 둔다

**항상 도는 잡**을 하나 만들고 그것만 필수로 건다.
판정은 그 안에서 명시적으로 한다.

```
skipped · success   통과   경로 필터로 안 돈 잡은 막을 이유가 없다
failure · cancelled  차단
```

`if: always()` 라 앞 잡이 실패해도 이 잡은 돈다.
그래야 *"실패했다"* 를 판정할 수 있다 — 안 돌면 pending 으로 남아
**보호가 영원히 안 풀린다.**

---

## 3. 되돌려서 확인한다

설정만 하고 끝내지 않는다. 이 저장소가 반복해 잡은 것이
*"선언은 있는데 안 도는 것"* 이라, 보호가 실제로 막는지 본다.

- 실패하는 PR 을 만들어 머지가 거부되는지
- 문서만 고친 PR 이 통과하는지

둘 다 확인한 뒤에 *"막힌다"* 고 말한다.

---

## 4. 이 사고에서 남는 것

**시험을 만들어 두는 것과 그 시험이 도는 것은 다르고,
도는 것과 그 결과가 반영되는 것은 또 다르다.**

| | 언제 겪었나 |
|---|---|
| 시험이 없다 | 초기 |
| 시험은 있는데 안 돈다 | 계약만 바꿨을 때 Gradle 이 건너뜀 · 경보 규칙이 CI 트리거 밖 (#167) |
| **돌긴 하는데 결과가 무시된다** | **이번 (#171)** |

세 번째가 제일 늦게 드러난다. **앞의 둘을 고쳐 놓은 뒤에야 보이기 때문이다.**
